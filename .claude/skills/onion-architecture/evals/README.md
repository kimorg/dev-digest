# onion-architecture evals

Test cases for the skill, run with skill-creator (with-skill vs without-skill): three reviews and
two generative tasks.

```
evals/
├── evals.json             # prompts, planted violations, decoys, assertions (the answer key)
├── trigger-evals.json     # should/shouldn't-trigger queries for description optimization
├── fixtures/              # inputs; the code carries no hints about what is wrong
│   ├── stale-pulls/server/src/modules/stale-pulls/             # eval 1: a module to review
│   ├── review-notifications/server/src/modules/notifications/  # eval 2: a module to review
│   ├── risk-badge/risk-badge.diff                               # eval 3: a diff to review
│   └── server-base/server/                                      # evals 4-5: trimmed server/src to edit
├── scripts/
│   └── diff_facts.py      # generative runs: changes.diff → diff_facts.json for the grader
├── workspace/             # local, gitignored — run outputs: iteration-N/eval-<id>-<name>/{with_skill,without_skill}/
└── description-optimization/  # local, gitignored — skill-creator run_loop results per timestamp
```

`workspace/` and `description-optimization/` are not committed: they are regenerated by every run,
and the conclusions are copied into [Results](#results) below.

Each fixture plants **3 structural violations** and 1–2 **decoys** (legitimate code that looks
suspicious). The answer key lives only in `evals.json`.

## Running without leaking the answer key

The runs must not see `evals.json` or this folder:

1. Copy each fixture to a neutral directory outside the skill (one copy per configuration).
2. Copy the skill **without `evals/`** (`SKILL.md`, `README.md`, `references/`) for the with-skill run.
3. Tell every run to read only its input copy (+ the skill copy), not to use the Skill tool and not to
   read the repo, so the baseline does not pick up the skill through `server/AGENTS.md`.
4. Each run writes its reply to `workspace/iteration-N/eval-<id>-<name>/<config>/run-1/outputs/review.md`
   (`run-K/` is the layout `aggregate_benchmark` expects; `timing.json` goes next to `outputs/`).
5. Grade **blind**: copy the replies under shuffled ids, give the grader only `evals.json` + the
   copies, map the grades back (`blind-map.json`) into `run-1/grading.json`.

Aggregate with skill-creator's `scripts.aggregate_benchmark`, view with
`eval-viewer/generate_review.py` (`workspace/iteration-N/review.html` is the static copy; local only).

## Models

Pass `model` on every Agent call; built-in subagents otherwise inherit the session model (Opus).

| Role | Model | Why |
|---|---|---|
| Executor, review evals 1-3 | opus | the skill's reviewers (architecture-reviewer) run on Opus |
| Executor, generative evals 4-5 | sonnet | implementer, which writes code with this skill, runs on Sonnet |
| Grader | sonnet | checklist with quoted evidence |

Keep one model per role within an iteration. The table applies from iteration-3 on: iteration-1 and
iteration-2 ran **all** executors on Opus 5.5, including generative evals 4-5, so compare their
eval 4-5 numbers with later iterations only with that caveat.

## Results

Run outputs are local (gitignored), so the numbers below are the record.

- iteration-1 (2026-11-15, evals 1-3 × 1 run): with skill 15/15, without 7/15. Both found all
  9 planted violations; the gap is fix quality (repo conventions) and false positives on decoys.
- iteration-2 (2026-11-17): 5 evals × 3 runs (Opus executors, blind Sonnet
  graders). With skill 100% ± 0%, without 71% ± 12%, at ~1.4× tokens. The baseline keeps missing the
  same conventions: adapter under `src/adapters/` + mock + container override slot, no server-only
  `vendor/shared` contract, `NotFoundError` instead of a hand-made 404.
- Description triggering (2026-11-17, `trigger-evals.json`, skill-creator `run_loop`):
  5 rewrites did not beat the original description (held-out 4/8 for all). No near-miss query
  triggered the skill (no interception of neighbouring skills), but should-trigger queries almost never
  did either. `run_eval` counts only the *first* tool call, so a model that explores the code before
  loading the skill counts as "not triggered"; treat these numbers as a lower bound.

### Generative fixture

`fixtures/server-base/` is a trimmed copy of the real `server/src` (container, mocks, schema, a clean
module `pr-history`, a legacy module `agents`). Generative runs edit a git-initialised copy; the
orchestrator saves `git diff` as `outputs/changes.diff`, and `scripts/diff_facts.py` turns it into
mechanical facts (`diff_facts.json`) that the grader checks against.
